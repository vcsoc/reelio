# Artwork And Subtitle Workspace

These features extend the unsigned developer preview. Sources are never edited in place; approve project changes and export to a new file to apply them.

## Posters And Covers

1. Open a video, then select **Poster & cover**.
2. Choose **Find artwork** if an image is already loaded, then enter the movie title/year and choose **Search posters**. A scrollable image browser displays Bing results directly inside the cover workspace, with thumbnails, source hosts, reported dimensions and **Use this cover** buttons. The desktop search toolbar keeps Movie title, Search, wide/tall orientation icon toggles, Image proportions and Results per page together on one row; narrow containers wrap compactly. The title selects all text on focus and shows a clear icon while nonempty. Landscape/portrait are icon toggles, not dropdown entries. Clicking an active orientation clears that filter; choosing the opposite orientation flips an exact ratio (for example 16:9 to 9:16), including 21:9/9:21. The ratio dropdown contains any, square, 4:3, 3:4, 16:9, 9:16, 2:3, 3:2, 21:9 and 9:21; Results per page offers 12/24/48. Changing either automatically refreshes the search from page one. Previous/Next navigates cached pages and fetches further provider batches as needed; totals are not invented. It never opens a separate browser window for this workflow.
3. Choose **Use this cover** on the image you want. That click authorizes the validated image download and immediately applies it to the current project, with no separate download/import confirmation or second Apply step. Exact ratio filters allow up to 4% difference in provider-reported aspect ratio; images without dimensions are excluded unless Any is selected. The downloaded image's real dimensions are checked again, then center-cropped to the exact integer ratio before applying, never stretched. Landscape/portrait verify orientation and preserve the source ratio. Project undo/redo restores the previous cover. Failed downloads or dimension mismatches leave the existing cover unchanged; choose a different result if an image host blocks access. Thumbnail downloads are limited to three concurrent requests.
4. Images are decoded, stripped of source metadata, flattened onto white if transparent and normalized to JPEG. Prepared originals are limited to 2048 pixels per edge and may be smaller to fit the 2 MiB cover limit. Only canonical JPEG data reaches the main WebView, never provider HTML/scripts. Search result HTML is parsed inertly with a 2 MiB limit per batch; provider pages are scanned in bounded groups (up to four provider batches per new UI page). Duplicate URLs are removed across the session. Sparse filters may yield fewer than the selected maximum results per page; Next can continue searching. Previous pages cache metadata, while thumbnails may reload. Safety limits are 40 cached pages or 1400 provider result positions; refine the search after that limit. Bing's actual async pagination is used rather than a query parameter that silently repeats the first results. The image downloads retain the public-HTTPS DNS-pinned importer limits. The search provider's markup can change or block requests, in which case Reelio reports an error or no selectable matches rather than silently opening another browser.
5. Wide desktop windows show the original, compact controls, and live preview in three columns. Narrow windows stack the panes. Help is available from information-icon tooltips. Crop by dragging the original or entering crop width/height; move a selection by dragging its interior and resize with its eight handles. The corner X clears the crop. Arrow keys move the focused selection or resize a focused handle (Shift: ten pixels). Escape/cancel discards a gesture; a completed drag creates one image-undo step. The redundant X/Y fields are removed. The crop lock icon optionally keeps proportions while changing dimensions; dimensions stay within the image and resize around the existing crop center. Poster 2:3/9:16, square, wide 16:9/3:2 presets, clear crop, image undo/redo, rotation, flip and reset use colorful icon buttons with tooltips. Resize has its own aspect-lock icon. Black and white, negative and sepia use sample-image toggle buttons with tooltips; the right-hand preview updates locally before painting, without substituting the original during asynchronous edits. Its raster work/output are bounded to 1280 pixels per edge. The backend JPEG remains authoritative for Apply; pending edits and active crop gestures cannot be applied before validation. Double-click brightness/contrast sliders or their labels to reset to 1.0. The editor has its own 40-step undo/redo history. Apply commits the edited result to the project, which also supports project-level undo/redo.
The upper viewer/lower workspace divider supports dragging, arrow keys (Shift: larger steps), Escape cancellation and Home/double-click reset. Its bounded height preference persists locally without editing the project. The artwork workspace defaults to a shorter viewer to leave room for all controls on ordinary wide desktops; deliberately small panes retain scrolling as a fallback.\n\n6. After optional image edits, choose **Apply cover to project** to commit the edited version. A confirmation appears beside Apply; global busy, error and success feedback stays visible while the workspace is scrolled. Download buttons show Applying while pending, and blocked hosts report their error immediately without changing tabs or losing the existing cover. Search selections are already applied immediately. The direct-URL confirmation and local image picker remain alternative import paths, with explicit Apply after editing. The image is embedded in saved project/job snapshots; the original image file remains untouched. A cover belongs to the output container, not to an individual video stream inside a multi-stream container.
7. Export to a new MP4/M4V or MKV. MP4/M4V receives attached JPEG cover art; MKV receives a `cover.jpg` / `image/jpeg` attachment. Output structure, cover dimensions and exact embedded JPEG bytes are verified before publication. Real-media tests also compare the copied video payload hashes.

This is a focused cover editor inspired by Pigeon's crop/rotate/resize and tonal tools, not a port of Pigeon's layered annotations, drawing, AI tools, or every image format. The input limit is 8 MiB, 8192 pixels per edge and 8 megapixels total; output resize is limited to 4096 per edge, 8 megapixels and a 2 MiB JPEG. Invalid edits cannot be applied. Large project files remain subject to the existing 4 MiB limit, including embedded artwork.

## Chapters And Source Preview

Chapter rows contain a title and a start time formatted as `HH:MM:SS.mmm`. Editing, adding, deleting or sorting chapter starts derives the required container end times from the next start or primary source duration; no separate end-time field is shown. Invalid clock text restores the previous value with an explanation. Existing imported end values remain intact until a timing/structure edit.

The inspector previews imported source video/audio, not cover art or pending track edits. Press Play after opening a source. Preview transport uses read-only, random-capability HTTP range URLs on IPv4 loopback rather than WebKit's unreliable custom-scheme media path. No transcoding or source mutation occurs. Retry preview reopens the selected source; failures distinguish stream access, decoding and format issues instead of assuming every failure is a codec problem. Playback still depends on platform codec support.

## Subtitle Search And Testing

1. Open **Subtitles**. Search uses Bing with an OpenSubtitles-focused query in the isolated Reelio browser. No API key is supplied by Reelio; provider accounts, download limits, licenses and site restrictions still apply.
2. Download and confirm an SRT/ASS/SSA/WebVTT file or a ZIP containing those files, enter a direct HTTPS URL, or choose local subtitle files.
3. Downloaded files are retained in Reelio's private application-data `downloads` directory. ZIP handling rejects traversal paths, links, unsupported/encrypted entries, more than 64 entries, more than 8 subtitle files, more than 4 MiB per subtitle or more than 16 MiB expanded text. Downloads are limited to 8 MiB. Only UTF-8 subtitle downloads are accepted; other encodings require explicit conversion outside this preview.
4. Choose **Add & test subtitle**. Downloaded files are not silently added as tracks: selecting a candidate imports it, and FFprobe checks the stream. Existing imported subtitle tracks can also be selected and tested.
5. Testing converts a temporary preview to WebVTT using FFmpeg; it does not change the original file or automatically approve export conversion. Cue inspection shows millisecond timing, up to the first 100 cue texts, seek actions and an out-of-duration warning. At most 10,000 cues / 4 MiB of preview text are accepted.
6. The source player displays script-created text cues after source metadata is ready. Use **Source to preview** if the project contains multiple playable source files. Play and seek to judge synchronization. The subtitle workspace keeps a compact player visible in narrow layouts as well.
7. Change track language/title/default/forced options as needed, then review the normal export plan. Nonzero offsets remain blocked; automatic release/frame-rate matching, OCR, style-perfect rendering and subtitle retiming are not implemented. Timing tests use ordinary zero-start synthetic fixtures; unusual container timelines still need qualification.

The cue inspector can work when a source codec is not playable in the platform WebView, but that is not proof of on-video synchronization. Styling and cue positioning may differ from the original subtitle renderer. Malformed-input coverage is not exhaustive; inspect the converted cue list before relying on it.

## Browser And Download Boundaries

- No network access occurs for ordinary local import/edit/export. Search is explicit and sends the displayed query, not a video upload. Websites in the search browser can contact their own third parties like an ordinary browser.
- Search windows use ephemeral browsing contexts. They have no Reelio file/edit/install API access: native custom commands check the main-window label and local origin, and core capabilities are scoped to the main window. Popups are routed into the same isolated browser. Non-HTTPS schemes, nonstandard ports, URL credentials and obvious local/private URL targets are rejected at top-level navigation; full public-DNS pinning applies to the importer. The browsing context is not a general-purpose network sandbox.
- The main workspace never embeds provider HTML or remote image URLs. Its CSP permits locally validated JPEG data images, not remote application scripts.
- Clicking **Use this cover** in the trusted internal gallery authorizes downloading and applying that selected image; search also authorizes bounded thumbnail requests. Direct-URL and subtitle/browser downloads retain their explicit confirmation dialog. Pending requests are bounded and cancellable. The importer permits HTTPS on port 443, validates and pins public DNS answers, rechecks redirects, disables proxies and rejects oversized/invalid bodies. DNS waits are bounded; HTTP operations share a 35-second deadline with up to four redirects. Resolver workers may finish after their wait deadline.
- For a browser-initiated download, matching browser cookies are used only for the original download host, not forwarded to different redirect hosts. Tokens/cookies are held transiently in memory, not saved to SQLite/projects or printed as request URLs. Direct subtitle URLs are not copied into exported track titles.
- Some sites use blob URLs, one-use links, anti-bot checks, browser-bound sessions or unusual download flows that the importer cannot reproduce. In those cases use a normal external browser to save the file and then use the local picker. Website-specific search/login/download acceptance remains manual; no universal provider compatibility is claimed.
- Downloaded subtitles are retained to preserve saved project references. Automatic cache garbage collection and a cache-management UI are not implemented.

## Required Components

The Arch package requires FFmpeg/FFprobe, GStreamer/base/good/libav, GTK/WebKitGTK, system CA certificates and Polkit. Debian metadata declares the corresponding media/tool/certificate packages. Image editing and ZIP handling are built into the Rust executable.

Startup and source changes check playback components before creating a player. Missing components disable preview instead of invoking the known missing-audio-sink crash path. **Install required components** or **Preferences > Install or repair components** uses fixed package allowlists through `pkexec` and the supported OS package manager (Arch-family or Debian/Ubuntu), with native confirmation and OS authorization. Repair reinstalls components where supported, never disables TLS verification, deletes package locks or performs a full distribution upgrade. A configured custom backend may still need correction in Preferences. Unsupported OS package-manager repair is reported rather than replaced with an untrusted download.

Windows/macOS native packaging, backend bundling and installer qualification remain open release work. This Linux implementation does not establish an unattended cross-platform dependency-install guarantee.
