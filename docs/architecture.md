# Architecture

## Dependency Direction

React -> typed IPC bridge -> Tauri commands -> application services -> domain policy.

The FFmpeg and SQLite adapters satisfy infrastructure responsibilities. Domain models import neither Tauri, SQLite nor process execution APIs. Seven independently useful crates implement domain policy, application coordination, FFmpeg, SQLite storage, bounded artwork transformations, bounded resource downloads and verified GitHub update downloads. Tauri-specific remote browser orchestration stays in the desktop adapter.

The project model owns stable asset IDs and track IDs. A track references `(asset_id, source_stream_index)`, never a display index. Array order specifies desired output order. The planner resolves compatibility for every enabled track and emits ordered output mappings. The process builder uses argument vectors and explicit `-map` and per-output-stream codec/metadata/disposition options. For MP4/M4V, the planner resolves a missing default to the first enabled track in output order for each media kind, without modifying the project's saved disposition flags or overriding an explicit enabled default. Each planned track carries its effective default; the argument builder writes it explicitly and output verification compares against the same resolved value. The UI marks implicit choices Auto and planner messages disclose them. Matroska dispositions remain unchanged; conflicting explicit defaults remain validation errors.

## State Ownership

- Zustand owns editable project snapshots and bounded undo/redo history (100 snapshots). Immutable JPEG strings are shared rather than deep-cloned with every edit. Source inspection is distinct from track settings; the cover editor separately keeps 40 transformation-option snapshots.
- React owns navigation, selection, notifications, dialogs and temporary inputs. Toolbar Project Tools share a horizontal Tabs provider with the workspace; project file actions use a separate keyboard menu. Its About dialog obtains a full compile-time Cargo-version/package-revision identity through trusted-main IPC; the homepage IPC has no URL parameter and launches only the fixed GitHub repository through an absolute system browser launcher. The main window is undecorated and the existing toolbar owns its chrome. A bounded `window_action` enum is dispatched only through the trusted-main IPC gate, with no new generic execution, navigation or Tauri capability grant. The custom close button confirms dirty state; `close()` still reaches Rust's active-job/component-repair close guards rather than force-destroying the window. Bounded persisted interface zoom is applied through trusted-main IPC to native WebView page zoom, independently of timeline time-scale zoom. Bounded/versioned localStorage preferences own panel widths, upper-left/full-height media-pool layout and independent sidebar visibility, never project snapshots or undo history. Hidden panels and the inactive lower timeline remain mounted so layout changes do not recreate the source player; the single artwork editor lives in the lower workspace.
- Rust owns active job identity and cancellation. SQLite owns durable job snapshots/status and monotonically increasing sequence numbers. Final crop/omission notices live in the existing progress JSON and are committed atomically with the completed status, not inferred from events; original job project snapshots remain unchanged.
- The UI polls metadata-only durable job summaries and ignores older sequence values. Full potentially cover-bearing snapshots are fetched only for explicit on-demand restore, validated and source-authorized. Events notify interested consumers but are not the only source of state.
- A native single-instance plugin focuses the existing window rather than opening a second database/job coordinator. One job can be reserved at a time. The reservation survives through verification and publication; native window close is blocked during an active job.
- Startup transitions nonterminal database rows to `interrupted`, never to completed and never to automatic retry.

## Update Downloads

`reelio-updates` owns numeric release/package comparison, platform asset matching, bounded GitHub HTTPS transport and exact-size/SHA-256 no-clobber downloads. Trusted-main IPC exposes check, native-chooser download and cancel, never a caller-provided URL/path or automatic installer. A single expiring native offer and serialized transient operation state are separate from persistent export jobs. Transfers extend native close protection; they do not modify projects or reuse export approval. See [updates](updates.md).

## Export Lifecycle

1. Validate model references, defaults, metadata syntax and chapter ordering.
2. Require session-authorized paths; re-probe sources and compare size, modification time, stream indices/types/codecs and probe properties.
3. Evaluate compatibility, resolve muted/mixed/language routing and effective defaults, and reject unsupported operations or unapproved conversion/rendering.
4. Pick a new destination in a native dialog. The backend independently rejects existing paths and source destinations.
5. Discover configured backend capabilities and check required muxers/encoders.
6. Create a unique temporary output, escaped FFmetadata chapter file and optional approved JPEG sidecar in the destination directory.
7. Execute FFmpeg directly, with file-only protocols, restricted demuxers, explicit maps, codecs and tags. Read machine progress and drain bounded stderr concurrently.
8. On cancellation, kill/reap the direct FFmpeg child and remove temporary files. The backend does not spawn a shell or helper process tree.
9. Probe temporary output; verify stream count/order/type/codecs, language, supported dispositions, labels, mapped metadata, chapters and duration tolerance. MP4/M4V chapter exports explicitly validate their auxiliary timed-text data stream. Optional covers have separate codec/dimension/metadata checks and exact extracted-JPEG byte comparison, rather than being mistaken for an ordinary mapped video track.
10. Recheck source fingerprints, sync file data, then persist without clobbering an existing destination. On Unix, best-effort sync the destination directory.
11. Record a terminal job result and release the active reservation.

The application does not claim universal atomicity or power-loss guarantees. Same-directory temp files avoid cross-filesystem rename. `persist_noclobber` may use platform-specific link/rename mechanisms; failure to finalize is reported without overwriting. A hard process/application crash may leave an identifiable `.reelio-export-*` temporary file. Startup records interruption but does not delete unknown files automatically.

## Project Format v1

`.reelio` files are UTF-8 JSON serialized from `reelio_domain::Project`. New project factories default to MP4; loading never replaces an explicitly serialized container selection. Schema 3 adds defaulted per-track `trim_start_ms` and optional absolute source `trim_end_ms` (exclusive); zero/null retain the original interval. Schema-1/2 files and job snapshots upgrade in memory without rewriting their files, preserving routing/muting (schema 1 defaults to unmuted Separate audio). Nondefault trim fields in legacy-version documents are rejected. Saving uses the existing atomic publication path. Older applications reject version 3 rather than silently ignoring trims. SQLite schema remains unchanged. Top-level keys: `schema_version`, `id`, `name`, `container`, `assets`, `tracks`, `metadata`, `chapters`, optional `artwork`. Missing artwork defaults to none for existing projects. Artwork contains canonical JPEG base64, dimensions and a bounded source label; actual JPEG content is decoded/validated at persistence and export boundaries. Unknown top-level keys and unsupported schema versions are rejected. MP4/M4V plans may prepend a disclosed Opening chapter at zero to avoid the muxer's nonzero-first-marker normalization; verification compares planned chapter starts/ends, not a mutated project model. References under the project directory are saved relatively. Moving a project does not move media. Relinking checks track indices/types; codecs are reconsidered by the planner.

Tracks contain IDs, source index, inclusion/title/language/dispositions and integer `offset_ms`. Offsets are non-destructive source-origin timeline positions. Trim bounds select a source interval without slipping its contents: its visible start is `max(0, offset_ms + trim_start_ms)` and output end is `offset_ms + (trim_end_ms ?? source_duration)`. Bounds require a known source duration, at least 10 ms of source material, and cannot extend outside the original file. Drag drafts are local; one pointer release commits one undoable edit. Capture loss/Escape/cancel discards drafts and suppressed synthetic clicks cannot insert chapters. The fit extent follows retained ends (including excluded clips), not original hours-long subtitle durations; original source bounds remain available for edge restoration/reset. Minimum-width snap activation uses the rendered edge, while the committed end remains an exact timestamp. Shared timeline zoom preserves cursor time over visible viewports and keeps the playhead visible otherwise; bounded native-scroll correction and suppression of programmatic feedback prevent fractional-WebKit rounding from accumulating across lanes. For video exports, output duration is the latest included real-video end; `fit_to_video` prepares an export-only clone and typed, stable-track-ID adjustments for audio/text-subtitle/chapter crops and omissions. The planner and argument builder use that same policy, without rewriting saved trim/offset values. Audio-only projects retain their original full timeline. Natural embedded audio codec padding of at most 50 ms beyond an untouched video's end remains copied. Stream DURATION clock tags are considered when direct per-stream duration is unavailable, so long embedded subtitles do not define a newly probed video's duration. Subtitle lanes with no retained cues are removed from actual output mappings; remaining mappings/defaults and cue verification indices are resolved again, with any default change disclosed in the job report. Muted audio lanes are omitted from the plan. Mix-role inputs collapse into one planned audio output carrying stable mix-source track IDs; separate language lanes retain independent maps. Mixing/positioning renders normalized 48 kHz stereo AAC at 192 kb/s, with trim/reset/delay filters generated from validated numbers. Video trims/positioning use approved H.264 CRF 18 rendering with trim/black padding at source-frame granularity. Text subtitle delays use dedicated file-restricted inputs; negative shifts stage owned normalized SubRip files with clipped/dropped pre-zero cues. Trims also normalize text through SubRip, clipping straddling cues at both source boundaries and dropping wholly outside cues before applying the output offset. Audio trim/reset/delay filters rebuild the post-padding sample clock with `asetpts=N/SR/TB` to avoid invalid AAC timestamps. Expected retained/shifted cue times are independently compared against extracted temporary-output cues before publication. All conversions/rendering require explicit export approval. No project field contains executable arguments or commands.

## Optional Search And Runtime Components

Poster search is an internal React gallery backed by inert, bounded Bing result-metadata parsing. Provider HTML/scripts are never executed or embedded; thumbnails pass through native image normalization with at most three concurrent requests, and a trusted local Use button authorizes immediate validated cover application. Subtitle search WebViews are ephemeral and have no main-window capability grant. Every custom native command checks the main label and local origin before dispatch. Browser downloads become expiring, bounded opaque selections; only local confirmation starts public-HTTPS DNS-pinned downloading and artwork/subtitle validation. Cookie transfer stays in the native adapter and never becomes a frontend-readable account store. Source media is not uploaded. See artwork-and-subtitles.md and security.md for restrictions and provider fallbacks.

The application dependency service checks FFmpeg/FFprobe, muxers/required subtitle encoders, GStreamer factories and the Linux HTTPS bundle. The frontend does not instantiate a media player while checks are pending or playback components are missing. Arch-family/Debian repair uses static package allowlists and absolute pkexec/package-manager paths, native confirmation, OS authentication and a concurrent-install guard. Package transactions are not timed out or killed; main-window closing is blocked during repair. Other OS installers remain unqualified.

## Dependency Locking

Direct dependencies use exact versions; `Cargo.lock` and `apps/desktop/package-lock.json` lock transitive resolution. Tauri 2.11.5 needs the matching 2.6.3 macro and 2.11.x runtime family in this lockfile: newer semver-compatible runtime/macros were experimentally incompatible. Do not regenerate the lockfile without building the desktop crate. FFmpeg is a system dependency and is not included in the application package.
