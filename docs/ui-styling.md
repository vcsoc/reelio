# UI Styling

## Timeline Workspace

The timeline revision preserves Pigeon's established charcoal/blue and light/system palettes while adopting the supplied DaVinci-style arrangement: media-pool cards/dropbox upper left, large source viewer upper center, per-stream timeline lanes below and a right inspector topped by a bounded cover image or Select a cover placeholder. The selected lane's title/language/routing live in that inspector. Video/audio/subtitle clips use blue/green/ochre accents, with red playheads and gold chapter pins. Timeline mode uses the full lower workspace instead of leaving an empty track-table panel. Project Tools retain all previous metadata, artwork, subtitle and export workflows.

Each audio/subtitle stream gets its own lane, with shared zoom and horizontal scroll so times remain aligned. Non-passive Alt-wheel handling prevents browser/page zoom and anchors time under the pointer across all lanes; virtualized rulers avoid unbounded tick DOMs at high zoom. One toolbar percentage button resets the shared view. Track controls sit in fixed-width left headers while the timeline spans beneath both media pool and viewer by default, closer to the supplied Resolve Edit/Cut references. The media-pool header's layout button switches to a full-height left panel with the lower workspace beside it. Independent toolbar buttons collapse/expand each sidebar, with dynamic tooltips and expanded state; these buttons remain outside their panels. All three layout choices persist in bounded, versioned localStorage independently of project history and panel widths, with in-memory operation if storage is blocked. Right-click/Shift+F10 opens a keyboard-accessible Include/Exclude menu; excluded clips are grey with an Excluded pill and remain editable. The viewer has a permanent seek/transport strip, with Ctrl-seek revealing the output playhead across all lanes. Both media-pool and right-inspector dividers support pointer/keyboard resizing and bounded, versioned localStorage preferences; unavailable storage does not prevent editing, and resizing never changes the project or its dirty state. Track, metadata, subtitle, chapter and export tools render inside the right inspector instead of adding a third row beneath the timeline. Selecting a tool reopens a collapsed inspector, including reselecting the active tool. Poster & cover instead occupies the existing lower timeline workspace, with a scrollable full-width browser/editor. Its gallery has no separate height-limited scroll container: the studio owns wheel scrolling through the last results and bottom controls, and result thumbnails keep their full proportions. Timeline restores the lanes without unmounting their component or the source viewer. The inspector retains only the compact cover preview/link while artwork is selected. Container-aware layouts stack metadata/artwork/chapter controls at narrow panel widths, and track settings use compact cards. The media pool uses left-aligned, two-line file rows with distinct kind icons and separate include buttons; its scroll area no longer shrinks the first file into a clipped thumbnail. A wider volume slider starts at 5% and shows its percentage. Seek input is explicit and coalesces pending positions while the decoder is seeking, preserving the scrub draft until the media catches up. Pointer capture keeps horizontal positioning reliable, canceled drags do not commit, and one completed drag is one undo step. Keyboard positioning and millisecond offset fields provide non-drag alternatives. Empty/selected cover states open the existing editor and update from project state immediately. Global feedback is portaled outside scrollable tool panels and stays visible on narrow screens.


Reelio's desktop styling follows the local Pigeon application's visual language (`~/Projects/pigeon/src/styles.css`). Pigeon is a read-only design reference; its source, settings and installed application are not modified.

## Toolbar And Interface Zoom

On desktop, the toolbar replaces the separate native title strip (`decorations: false` for the main window). Existing navigation, project actions and Export remain in that top bar, with a matching right-edge minimize/maximize-or-restore/close group. Unused chrome and the brand handle left-button window drag/double-click maximize; interactive controls, menus and dialogs are excluded. The custom Close button confirms unsaved changes; native export/repair protections remain authoritative. At very narrow effective native widths, action/tools rows wrap beneath the window controls. Browser preview has no fake desktop controls.

Project actions move into a keyboard-accessible hamburger immediately before the left-panel toggle. New/Open/import/Save retain the same guards, shortcuts and native handlers. Add tracks is a compact plus-and-label button directly in the Output Timeline header, not a hamburger item; it invokes the existing media chooser and stays disabled while busy. Header controls wrap at narrow widths without hiding the action. The menu supports arrows, Home/End, Escape/Tab, focus return, outside-pointer dismissal and disabled actions while busy; its stacking context stays above sticky feedback notices. Project Tools leaves the media sidebar for horizontal toolbar tabs. At limited container widths, labeled icons with tooltips replace text; at 1050px and below the tools get a second toolbar row rather than overflowing. Both sidebar toggles and navigation remain accessible with panels collapsed. About Reelio is a native HTML modal in the same palette, with full installed version/build, Chris Visser developer credit and a focusable GitHub link; Close/Escape returns focus to the menu trigger. Browser preview is explicitly labeled rather than displaying a guessed installed version.

The viewer project-name field has no idle border, background or shadow; keyboard focus retains its outline. Both the viewer project name and poster movie-title field use explicit high-contrast blue/white selection colors in both themes, distinguishable from the unselected caret state. The viewer title caret follows the theme's text color; full and partial selection do not modify the project name. New projects select MP4 in both frontend and Rust factories; serialized formats are never migrated or overridden, and conversion/render approval remains mandatory. The export inspector omits the permanent notices block and authorization checkbox. Starting an export reviews warnings on demand, identifies any converting/rendering tracks and requests fresh approval; canceling starts nothing. Validation errors and per-track action badges remain visible. Video-led exports announce completion with their actual crop/omission count and show a persistent per-job adjustment report (names, stable track identities and retained intervals) in history. Empty subtitle lanes are explicitly reported, not silently discarded; failed/cancelled exports replace the stale start notification. Project clips themselves are not shortened by export.

Ctrl/Cmd+plus/equals and minus adjust whole-interface zoom by 10%, bounded to 50..200%; Ctrl/Cmd+0 and the footer percentage reset it. The versioned local preference does not dirty projects. Trusted-main IPC validates a bounded integer before using native WebView page zoom, with ordered frontend requests; no extra Tauri capability or general-purpose command is exposed. Browser preview uses approximate CSS zoom only. Timeline Alt-wheel zoom remains independent. Its fit extent follows retained clip ends rather than original long subtitle durations, including excluded clips for restoration. Magnetic trim activates at the actual visible edge even when the clip is rendered at minimum width. Native scroll quantization is corrected in bounded steps, and programmatic synchronization does not feed rounded offsets back across lanes.

## Shared Visual Language

- Charcoal workspace `#18191b`, sidebar/inspector `#202123`, and toolbar `#1b1c1e`.
- Blue accent `#5688ff`, slate selection `#34394c`, pale foreground `#e8eaf0`, and muted labels `#8f95a6`.
- Compact 40px desktop toolbar, 29px navigation rows, 30px status bar, thin dividers and small control radii.
- Pigeon's Inter/system sans-serif stack, compact property labels, tabular numeric values, and restrained blue-gradient primary actions.
- Dense track rows and metadata forms, source-preview cards, blue selected controls and neutral dialogs.
- A compact media-oriented empty state instead of the previous green/serif promotional layout.

Implementation: `apps/desktop/src/app/styles.css`. Theme variables keep the dark and light palettes consistent across navigation, tables, forms, previews, notices, progress and dialogs. Success, conversion warnings and errors retain distinct semantic colors rather than all becoming blue.

## Preferences And Responsive Behavior

New profiles default to dark appearance. Existing saved light, dark or system preferences remain authoritative; no setting migration or reset is performed. System appearance follows changes to the OS color scheme. No remote fonts, images, scripts or other network resources are introduced.

Native window controls, Tauri permissions, project editing, undo/redo, export planning and media processing remain unchanged. At 1050px and below, the inspector stacks beneath the viewer/lower workspace; at 640px and below, all visible sections stack vertically. Saved full-height preference is retained for wider windows, and independent collapse controls still work on narrow screens. Icon-only mobile toolbar actions avoid horizontal overflow, and navigation scroll targets leave room for the sticky toolbar. Focus indicators, native dialog focus containment and reduced-motion support are preserved.

## Regression Checks

The Playwright suite checks the dark surface colors, compact toolbar height, saved light-theme behavior, dark/light/system transitions, appearance-setting IPC, settings dismissal, viewport overflow, and the existing import/edit/save/export-plan flow using mocked native IPC. It captures dark empty-state, dark/light export and dark settings screenshots for both desktop and narrow viewports under `apps/desktop/test-results/`.

These are UI and mocked-IPC tests, not claims of native file-dialog or media-backend acceptance. The application is still the developer preview described in `implementation-status.md`.
