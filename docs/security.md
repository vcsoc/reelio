# Security And Data Safety

## Current Controls

- No shell execution, frontend filesystem plugin, mandatory account/API key, or telemetry. Poster search uses an inertly parsed internal gallery with validated JPEG thumbnails, never remote HTML/scripts. Explicit Use buttons authorize immediate cover application. Subtitle search uses isolated remote browser windows; direct/subtitle downloads retain local confirmation and bounded validation; see artwork-and-subtitles.md.
- Native dialogs and native drop events authorize individual canonical local source paths for the current session. Explicitly choosing a validated `.reelio` project authorizes its existing referenced files automatically, including references outside the project directory; there is no second source-confirmation dialog. Only open projects you trust. Parsing/path validation, individual canonical-file grants and source/export checks remain enforced; no whole-directory grant is added. Job-snapshot restoration retains its separate confirmation. Asset preview scope is granted one file at a time, not a whole directory. Source playback additionally uses a lazy read-only loopback HTTP transport after `require_authorized`: random UUID capabilities reference open regular-file handles, not URL-supplied filesystem paths. It binds only `127.0.0.1`, validates the exact Host/port (including duplicate-host rejection), serves only GET/HEAD, exposes no directory listing and keeps at most 72 source handles for multi-lane audition. On Unix, repeat registrations reuse an existing capability only when path, open-file device/inode, size and mtime all match; replacements receive a new token. Unknown/evicted tokens fail closed; size/mtime changes are rejected. Headers are limited to 16 KiB / five seconds, sixteen workers and 64 KiB transfer buffers; range responses stream the exact requested interval, bounded by the authorized file's captured length, rather than truncating at an arbitrary byte/time boundary that WebKit can mistake for EOF. Read/write idle socket waits are limited to five seconds; continuous active media transfers may last longer than 35 seconds, but retain the fixed worker/handle/buffer limits. Header parsing still has a five-second total ceiling. No whole-file buffer is allocated. Responses are no-store and do not grant cross-origin read permission. Only media-src gains loopback HTTP access; remote resource import remains public-HTTPS-only, and loopback pages cannot invoke privileged commands.
- Native source opening is limited to regular files. FFprobe/FFmpeg use a file-only protocol whitelist and a conservative demuxer whitelist; network/playlist demuxers are not enabled.
- JPEG/PNG/WebP still-image signatures are read from at most 12 bytes and select existing literal single-file pipe demuxers for probe/decode. Recognized images over 8 MiB are rejected before probing. The `image2` sequence demuxer is not enabled and filenames/patterns do not determine image format.
- Probe requests have a 30-second timeout and an 8 MiB stdout/stderr bound. Backend discovery has a 15-second timeout. Export stderr is drained with a bounded tail; progress flows over a bounded channel.
- JSON project files are limited to 4 MiB; model limits bound assets, tracks, chapters, titles, offsets and tag sizes. Schema versions are checked. Timeline projects use schema 3; schema-1/2 projects/snapshots upgrade in memory with untrimmed source intervals and preserved routing, while older apps reject version 3 rather than ignoring trims. Legacy documents containing nondefault trim fields are rejected. Trim bounds require a known bounded source duration, at least 10 ms of retained source material, and a nonempty visible interval; no extension beyond source bounds or unknown-duration trimming is accepted. Audio role is an enum, positions are bounded to 24 hours, duration fields are bounded, mixed input counts and positioned subtitle/render output counts are capped at 64. Filters use only validated numeric values and source indices, never titles or paths. Rendering requires explicit approval. Subtitle trims/negative offsets stage private temporary SubRip files with 4 MiB/10,000-cue bounds; output cue timing is verified before no-clobber publication. A known positive planned duration cannot be accepted with an absent/zero probed output duration.
- Existing export destinations are refused twice: before processing and at no-clobber publication. Sources are never passed as write targets. Project saves use native save authorization and do not replace selected source paths.
- Export settings from imported projects are not executable commands. All FFmpeg arguments are built from validated fields.
- SQLite queries are parameterized. Migrations are transactional, foreign keys enabled, and future database versions rejected. Failure never triggers database deletion or silent reset.
- The main workspace's restrictive CSP excludes remote scripts/frames/objects; validated JPEG data images are allowed. Core capabilities are scoped to the main window. Every custom native command additionally checks the main label and local origin, preventing isolated remote search pages from invoking file/edit/install commands.
- HTTPS imports validate/pin public DNS results for each redirect, disable proxies, limit redirects, enforce TLS, cap bodies at 8 MiB and bound DNS/HTTP waits. Browser session cookies are transient and only sent to the original download host; request URLs and cookies are not logged or persisted as project metadata.
- Image decoding has byte/dimension/allocation limits and only accepts JPEG/PNG/WebP; canonical JPEG derivatives strip source metadata. Subtitle ZIPs have path/link/entry/expansion limits and never execute contents. Subtitles are parsed through the restricted FFmpeg backend before testing.
- Runtime dependency checks keep the source player disabled when playback elements are missing. The only elevated operation is a native-confirmed fixed OS package allowlist via absolute pkexec/package-manager paths. It never installs downloaded provider files, disables TLS verification or removes package locks.

## Release Checks And Downloads

Manual update checks use fixed HTTPS GitHub endpoints, bounded pagination/metadata and numeric version/platform matching. Only checked expiring native offers can be downloaded; the frontend cannot supply a URL or destination path. A native chooser approves the destination, then exact-size/SHA-256 verification and same-directory no-clobber publication protect existing files. Redirect hosts and transfer limits are checked; signed URLs are not included in request errors. There is no automatic installer execution or elevation. Unsigned release checksums are integrity evidence, not independent signing/authenticity. See [updates](updates.md) for cancellation, timeout and crash-cleanup limits.

## Residual Risks And Boundaries

FFmpeg and WebView decoders are native untrusted-input parsers, not a sandbox. A malicious local media file may exploit a backend vulnerability or consume memory before output limits trigger. Keep FFmpeg, the OS WebView, Rust/JS dependencies and Tauri current. Source authorization does not prevent every filesystem race or local-file indirection inside a demuxer. Modification-time/size fingerprints are not cryptographic source identity.

Export jobs do not have a wall-clock timeout because legitimate large-file remuxes can be long. Cancellation remains available. There is no disk-free-space preflight, process memory quota, privilege separation, or diagnostic-bundle redaction layer yet. Native process crashes/power loss can leave temporary files; sources and pre-existing destinations remain untouched by the normal workflow, but underlying filesystem failure is outside the application's guarantee.

Raw backend/engine errors may contain local paths or provider/source diagnostics; they are shown only in the local UI/console. Do not share them without reviewing them. Remote browser cookies may exist transiently in memory, but account passwords/API keys are not stored in SQLite/projects. Persistent provider credential storage, file-log redaction/rotation and portable diagnostics remain unimplemented. The isolated browser is not a general-purpose network sandbox, and provider-specific login/download flows still require manual qualification.

The release workflow builds **unsigned** artifacts only. Dependency license review, signing, notarization, vulnerability triage and native cross-platform acceptance are release blockers. Do not redistribute FFmpeg without reviewing the particular build's license and codec obligations.

## Database Recovery

The database lives under Tauri's platform application-data directory as `reelio.sqlite3`, with SQLite WAL/SHM siblings as needed. If opening or migrating fails, Reelio stops without resetting it. Close Reelio, back up the database **and its WAL/SHM files together**, and inspect a copy with SQLite tooling. Do not delete the only copy. Native `.reelio` project files are independent of the state database.

## Reporting

Do not post private media, provider credentials, personal paths, or unredacted logs in a public issue. Reproduce with a synthetic fixture where possible. A security contact and coordinated disclosure process must be established before public distribution.
